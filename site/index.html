One table that tells you if any Kamal app is broken.

kamal-panel reads the state Kamal already leaves on your servers — docker ps, kamal-proxy list — over SSH, and shows it as a single apps × hosts table. Deploys still run from your CI with kamal deploy.

The panel deploys with Kamal, just like your apps. The install guide covers secrets and the first admin account.

git clone https://github.com/wenlingang/kamal-panel.git && cd kamal-panel
bin/rails db:encryption:init   # keep these keys safe
# set image, servers.web and proxy.host in config/deploy.yml
bin/kamal setup

What it is, and what it isn't

It is

  • A mostly read-only view of every Kamal app on every host.
  • The place to roll back, restart, stop, start or unlock when something is wrong.
  • Self-hosted: one container, SQLite, no Redis, no Postgres.

It isn't

  • A replacement for Kamal — it calls the same kamal CLI you already use.
  • A deploy pipeline — deploys stay in your CI.
  • A metrics or log aggregation platform.

Built for the moment something breaks

See drift before your users do

When one host is still on the old version, the whole app turns amber. Unhealthy containers and unreachable machines each get their own colour.

Know who deployed what

Pre-deploy and post-deploy hooks report the person, the command and failed deploys. Without the hook, the panel still records a deploy whenever it sees the version change.

  • Drift and health

    Version drift, unhealthy containers and unreachable hosts, at a glance.

  • Deploy history

    From your hook, or inferred by the panel when versions change.

  • Fix in place

    Roll back, restart, stop, start and force-unlock through the kamal CLI. Every action is audited.

  • Three roles

    admin, developer and ops. Developers act only on the apps they belong to.

  • Write-only credentials

    SSH keys and registry passwords are encrypted at rest and never shown again after saving.

  • English and 中文

    The whole interface, emails included, in English and Simplified Chinese.

Treat it like an SSH key

  1. The panel is as secure as the servers it manages. Anyone who can reach it and read its database can act on your infrastructure.
  2. Adding an app runs code. Parsing deploy.yml evaluates ERB, just as Kamal does. Only trusted admins should add apps.
  3. Keys are write-only. Stored with Active Record encryption; the UI shows a fingerprint, never the key.
